# Feedback Collection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let signed-in users leave a 1–5 rating and/or a comment from a footer link, the user menu, or an inline "How was this session?" strip in the chat. Each submission is written as one `event=feedback` JSON log line.

**Architecture:** A new `internal/web/feedback.go` holds `GET /feedback` (a server-rendered form page) and `POST /feedback`. The POST handler serves two callers: the HTML form (field CSRF, renders a page) and `chat.js` (header CSRF, returns a bare status code). Nothing is stored; the handler logs through the existing `slog` JSON logger.

**Tech Stack:** Go 1.x `net/http` + `html/template`, `log/slog`, vanilla JS (`chat.js`), plain CSS. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-25-feedback-design.md` (companion: `docs/feedback-collection-options.md`)

## Global Constraints

- **No commits by the agent.** The user's global CLAUDE.md says "NEVER commit on behalf of user". Each task ends by staging its files and reporting; the user commits.
- No new config keys and no new Go modules.
- CSP stays as it is: no inline scripts or styles. User text goes into the DOM only through `textContent`.
- Rating: integer 1–5, optional. Comment: optional, at most **2000 characters** (runes) after `strings.TrimSpace`. At least one of the two is required.
- `source` is one of `footer` | `menu` | `chat`; any other value becomes `footer`.
- `from`: kept only if it starts with `/`, does not start with `//` or `/\`, and is at most 512 bytes. Otherwise it becomes `""`.
- `conversation`: kept only if `a2a.ValidUUID` accepts it.
- Rate limit: 10 submissions per user per hour, keyed by the session's cap key. The over-limit message is exactly "You've sent a lot of feedback recently. Please try again later."
- Log call: `s.log.Info("feedback received", "event", "feedback", ...)`.
- Copy: page title "Rate your experience"; textarea label "Anything else you'd like to tell us?"; scale labels "1 – Poor", "2", "3", "4", "5 – Excellent"; thanks text "Thanks for your feedback"; link text "Give feedback"; strip text "How was this session?".
- Release v0.6.0 is a git tag (the version comes from `-ldflags`). Tagging is left to the user.

## Review Focus

1. **The footer pushes the chat composer off-screen.** `.chat-layout` is `height: calc(100vh - 48px)` (and the mobile variant). Adding a footer must subtract its height, or the cluster page scrolls and the composer is hidden. Task 2 sets a `--footer-h` variable and a template test checks that the footer is present; checking the layout itself is a manual step in Task 4.
2. **A transcript redraw wipes the strip.** `renderTranscript` calls `clearLog()` on `#log`. The strip must live outside `#log` (a fixed element in `cluster.html`), or it disappears during follow polling. This is pinned by the markup test in Task 3.
3. **A multi-byte comment near the cap is wrongly rejected.** 2000 CJK characters are 6000 bytes, plus URL encoding (×3 = 18 KB). The body limit is 32 KiB, not the shared 4 KiB `maxFormSize`. Test `TestFeedback_CommentMultibyteAtCap` in Task 1.
4. **Open redirect or HTML injection through `from`.** `from` is only logged and echoed back as a hidden field (html/template escapes it), and is never used as a redirect target. Tests `//evil.example`, `https://evil.example` and `/\evil` in Task 1.
5. **The strip shows when the reply isn't really finished.** A `done` event after an `ask` (`input-required`), after an error, or while following a turn must not show it. The JS condition is `gotDone && !errored && !asking`; this is verified manually in Task 4 against the fake Rancher's `<site>-stg-23` (failed) and an ask_user flow.

**Interfaces:**
- Produces:
  - `func (s *Session) Key() string` in `session` returns `capKey(s)`. The private `capKey` stays and the method wraps it.
  - `server.fbLim *ratelimit.Limiter`, created in `build` as `ratelimit.New(10, time.Hour, s.now)`. **Note:** tests replace `srv.now` after `build`, so the limiter must read time through a closure (`func() time.Time { return s.now() }`), not the method value captured at build time.
  - Routes `GET /feedback` → `s.feedbackPage`, `POST /feedback` → `s.feedbackSubmit`.
  - `pageData` gains `Feedback feedbackForm` and `Path string` (Path is used by Task 2).
  - `type feedbackForm struct { Rating int; Comment, Source, From, Conversation string; Sent bool }`
  - `func cleanFrom(raw string) string`, `func clusterOf(from string) (site, cluster string)` (parses `/clusters/{site}/{id}` from the path part, path-unescaped; empty strings otherwise), `func conversationOf(from string) string` (the `c` query param of `from` if it's a valid UUID).
  - Constants: `maxFeedbackForm = 32 << 10`, `maxFeedbackComment = 2000`, `feedbackPerHour = 10`.

Handler behaviour:
- **No session.** GET → `303` to `/`. POST → `401` with header CSRF, `303` to `/` without.
- **API mode** is `r.Header.Get("X-CSRF-Token") != ""`. CSRF is checked with `subtle.ConstantTimeCompare` against `sess.CSRF`, using the header in API mode and the `csrf` form field otherwise. A mismatch returns `403`.
- **Order of checks:** CSRF, then parse (`http.MaxBytesReader` with `maxFeedbackForm`, `setBodyDeadline`; oversize → `413`), then validate (`400` in API mode, or the form re-rendered with code 400 and an error message), then `fbLim.Reserve(sess.Key())` (`429`; in form mode the form is re-rendered with code 429 and the limit message), then log, then success (`204` in API mode, or the page rendered with `Sent: true` and code 200).
- **Validation messages (form mode):** "Pick a rating or write a comment." / "Your comment is too long (2000 characters max)." A rating outside 1–5, or one that isn't a number, gives `400` "Pick a rating from 1 to 5."
- **Log attributes, in this order:** `feedback_id` (`a2a.NewUUID()`), `username`, `principal`, `rating` (0 when not given), `comment` (trimmed), `source`, `page` (the cleaned `from`), `site`, `cluster`, `conversation` (the form value, else `conversationOf(from)`), `version`.
- **GET** renders `feedback` with `Feedback.Source` (cleaned `source` query param) and `Feedback.From` (cleaned `from` query param). The template posts `rating` (radio, values 1–5), `comment` (textarea `maxlength="2000"`), and hidden `csrf`, `source`, `from`.

### Task 3: "How was this session?" strip in the chat

**Files:**
- Modify: `internal/web/templates/cluster.html`: add `<div id="feedback-strip" class="feedback-strip" hidden></div>` **between `#log` and `.composer`**, outside `#log`. Add `data-feedback-url="/feedback"` and `data-page="{{.Path}}"` on `#chat`.
- Modify: `internal/web/static/chat.js`
- Modify: `internal/web/static/style.css` (`.feedback-strip`)
- Test: `internal/web/feedback_test.go`

**Interfaces:**
- Consumes: `POST /feedback` in API mode (Task 1): `X-CSRF-Token` header, body `URLSearchParams` with `rating`, `comment`, `source=chat`, `from` (= `ds.page`), `conversation` (= `contextId`); 204 means success. `.rating-scale` (Task 2).
- Produces: `function maybeFeedback()` and `function showFeedback()` inside the chat IIFE.

Behaviour:
- In `run()`'s `finally`, on the `ready(true)` branch only, call `maybeFeedback()`. It returns unless `gotDone && !errored && !asking`, and unless `sessionStorage.getItem('fb:' + contextId)` is unset. Otherwise it sets that key to `'1'` and calls `showFeedback()`. Wrap the `sessionStorage` calls in try/catch; if storage is unavailable, show the strip anyway.
- `showFeedback()` fills the strip with: the label "How was this session?", five buttons "1"–"5" (`aria-pressed`), and a × button (`aria-label="Dismiss"`). Picking a rating reveals a textarea (`maxlength=2000`, placeholder "Anything to add? (optional)") plus Send and Skip buttons. Send posts the rating and comment; Skip posts the rating only. On 204 the strip's content becomes "Thanks for your feedback". On any other status or a network error, show "Couldn't send feedback" and re-enable the buttons. × hides the strip and posts nothing.
- When the user starts a new message (`send()`), hide the strip if it is showing and unanswered.
- Never call `maybeFeedback` from the replay or follow paths (`renderTranscript`, `loadTranscript`).
